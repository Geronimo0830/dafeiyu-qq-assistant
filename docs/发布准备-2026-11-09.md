## 实际验证

- 190 项 Python 测试全部通过。
- 实际 EXE 使用隔离的临时目录和用户数据目录启动：自解压、嵌入式 `pythonw`、安装向导后台正常；空闲退出后自解压目录自动清理。
- 对最终 EXE 的内嵌归档进行完整性检查并解包。
- 用包内 Python 启动正式向导，通过实际安装接口解出完整载荷，确认程序与用户数据分别进入 `program/` 和 `userdata/`。
- 安装流程停在等待 API 凭据的位置，未提交真实密钥、未启动 QQ 登录。
- 语音和长期记忆默认关闭；安装后的四份项目许可文件与启动包一致。
- 同一安装目录再次启动时复用现有后台；中断后能重新进入安装向导；后台可以正常退出。
- 构建中的 AstrBot 后台已实际启动，十个插件安装与配置步骤通过，语音试听明确跳过。

测试运行证据保存在本机构建目录 `.tmp/`，不随源码上传。真实 QQ 扫码与聊天、付费语音和向量接口、完整旧版升级以及真实环境卸载仍需后续验收，因此本次发布为预览版。

## 构建输入与第三方材料

输入为 Python 3.12.10 嵌入式运行时、get-pip.py、reduced 7zr.exe、LZMA SDK 25.01、AstrBot 4.29.3 源码与后台资源，以及 NapCat v4.18.41 Node 版。

AstrBot 后台与 NapCat 发行资产的 SHA-256 已与 GitHub 官方资产摘要核对一致；其他输入记录本地 SHA-256 和来源，不声称已完成官方签名验证。公开的 `input-manifest.json` 不包含构建机器的绝对路径。

Python、Node.js、NapCat、SDK/SFX 许可及来源记录随安装包保留。`program/licenses/python-dependencies.json` 和 `python-requirements-lock.txt` 记录本次实际安装的 169 个 Python 分发包。源码和插件市场依赖可能变化，版本清单不等于完整的可重复构建保证。

Release 附有 `ThirdParty-Sources-v0.1.0-preview.1.zip`，包含本次 AstrBot 原始源码归档、安装包中的插件源码、配置包及运行时许可材料，并提供 SHA-256。第三方源码继续使用各自许可证。
